# ADR-0004: 面板列表 `<nav>` 的发现不再依赖「直接子元素」

**Date:** 2026-11-12
**Status:** Accepted
**Author(s):** dsh-toomuch-plugins maintainers
**Deciders:** 插件维护者

---

## Context

用户报告（2026-11-12）：dsh 升级到 v0.2.2-rc.2 后，「全局面板」这一列变成**和
工作区一起上下滚动**，同时本插件的**网格显示功能整体失效**（勾了「网格方式显示」
也没反应），折叠与显示顺序一并失灵。

对照 `@deepseek-ai/dsh-client-ui-sidebar` 的源码与构建产物，rc.2 的侧栏 DOM 变成：

```
div.root                       ← 侧栏根节点
├─ div.logoRow
├─ button.newSession
├─ div.scrollRegion            ← 新增：滚动视口
│  └─ div.scrollArea
│     ├─ nav.panelList         ← 面板列表挪到了这里
│     └─ div.regionArea        ← 工作区区域，和面板列表同一个滚动视口
└─ div.footArea                ← 本插件的开关在这里
```

而 ≤ v0.2.2-rc.1 是：

```
div.root
├─ div.logoRow
├─ button.newSession
├─ nav.panelList               ← 面板列表是根节点的直接子元素
└─ div.regionArea
```

本插件 0.4.0 之前的发现逻辑是「从开关往上逐级找第一个含**直接子** `<nav>` 的祖先」。

**为什么这样就失效了：** 新结构里 `<nav>` 的祖先是 `scrollRegion > scrollArea`，
而开关的祖先链是 `footArea > root` —— 两者是**兄弟子树**，`<nav>` 根本不在开关的
祖先链上。回溯从开关走到 `document.body` 也不会经过它。于是 `findPanelNav()` 返回
null，`applyGrid()` / `applyNav()` 全部提前返回。

后果是**静默失效**：网格不生效、折叠不生效、显示顺序不生效、绕槽条目不再被收养，
但界面不报错、不变形——用户看到的是「设置项还在、勾了没用」。

同一轮改版里还有第二个变化：rc.2 起 DSH 把每个面板行包进了自己的**格子**
（`div.panelEntry > button.panelRow`），rc.1 时 `<nav>` 的直接子元素就是按钮本身。
这让「收起时保留前 N 行」在 rc.2 下即使找到 `<nav>` 也会留下空格子：按行（按钮）
隐藏，格子还在，网格里就多出一排空位。

**Key constraints:**

- 设计文档（docs/design.md）既定边界：不注入 DSH 内部模块、不读写 DSH 配置、
  偏好只写 `localStorage`；安全失效（找不到目标元素时什么都不做、不报错）。
- 本插件不 import DSH 内部包，class 名可能被构建工具 hash（`.hHd-Xa_panelList`），
  只能用结构关系定位。
- 必须同时支持 rc.2 与 rc.2 之前的版本——用户的 profile 上两种都可能存在。
- 侧栏里还有别的 `<nav>`（设置页的分类导航），不能只看「有没有 nav」。

---

## Options Considered

### Option 1: 只在侧栏根节点子树里找第一个 `<nav>`

**Description:** 认定侧栏里只有一个 `<nav>`（面板列表），从根节点子树里直接取。

**Pros:** 代码最短，一次查询搞定。

**Cons:** 设置页的分类导航也是一个 `<nav>`；一旦设置面板打开、或者将来侧栏里再加
一个导航区，就会认错对象 —— 认错的后果是**把别人的列表折叠 / 改成网格**，不是安全失效。

**Why this was ruled out:** 拿「弄坏别人的界面」换「少写几行」，不划算。

### Option 2: 用 class 名（`nav[class*="panelList"]`）定位

**Description:** 照抄第三方插件（今日值得读等）的做法，用 class 名片段匹配。

**Pros:** 精确，不会认错；代码最短。

**Cons:** class 名是构建产物里的 hash 前缀（`hHd-Xa_panelList`），构建器一改就失效——
这正是设计文档当初不写死 class 的原因（ADR-0001 同款理由）。

**Why this was ruled out:** 把「安全的结构关系」换成「可能整体失效的 class 名」。

### Option 3: 结构判定 + 侧栏根节点另找一次（**选中**）

**Description:**
1. **面板列表判定**：`isPanelNav(nav)` —— `<nav>` 里有带 `aria-label` 的按钮
   （DSH 的 `PanelRow` 恒有 `aria-label`；设置页那个 `<nav>` 的按钮没有）。
2. **发现路径**：从开关往上逐级，每一层先看「直接子 `<nav>`」（rc.1 的形状），
   再看「这一层子树里第一个装面板行的 `<nav>`」（rc.2 的形状）。
3. **侧栏根节点**：第一个「子树里装着面板列表」的祖先。它不再是 `<nav>` 的父节点，
   但绕槽条目（`data-dsh-*-entry`）仍挂在它上面，收养 / 放回都要找它。
4. **计数单位**：一行 = `<nav>` 的**直接子元素**（rc.1 是按钮，rc.2 是 DSH 的格子），
   隐藏按格子隐藏，网格里不留空位。

**Pros:**

- 新旧两种形状都认，且旧形状的判定路径原样保留。
- 认错对象的风险被 `aria-label` 这条结构特征挡住：认不出就什么都不做（安全失效）。
- 顺手修掉 rc.2 的格子问题：收起限额按格子算，网格里不留空位。

**Cons:**

- 「面板行是带 `aria-label` 的按钮」是结构推断，不是官方契约；DSH 若改掉 `aria-label`，
  插件会退回安全失效（什么都不做），不会弄坏界面。
- 多了一次子树查询（每次渲染走几层祖先），可忽略。

**Why this was ruled out (if not chosen):** —— 即所选方案。

### Option 4: 把面板列表挪出 DSH 的滚动视口 / 反过来把 DSH 的结构改回去

**Description:** 让本插件接管侧栏结构，或给 DSH 提需求。

**Pros:** 结构稳定，问题从根上消失。

**Cons:** 改不了上游；本插件一旦自己接管渲染，就要跟着 DSH 的每一次改动走。

**Why this was ruled out:** 同 ADR-0001 的 Option 4——治本方向正确，但不是这次修复的手段。

---

## Decision

**We will 用结构判定找面板列表（Option 3）：`<nav>` 里有带 `aria-label` 的按钮才算；
发现路径新旧两走；侧栏根节点另找一次；收起限额按 `<nav>` 的直接子元素（格子）算。**

四件事：

1. `isPanelNav(nav)` / `panelNavIn(scope)`：判定与查找；
2. `findPanelNav(from)`：祖先链上先「直接子 `<nav>`」后「子树里的面板列表」；
3. `findSidebarRoot(from)`：第一个子树里装着面板列表的祖先——收养 / 放回按它走，
   放回时插到记录下来的相邻元素之前（`<nav>` 不再是根节点的子元素时退回追加）；
4. `applyNav()` 按 `<nav>` 的**直接子元素**排序与隐藏（`orderOf(cell)` + 视觉序），
   `applyGrid()` 把 `title` 镜像到格子里的那一行按钮上（`rowOf(cell)`）。

---

## Consequences

### Positive Consequences

- rc.2 与 rc.1 两种形状都恢复：网格、折叠、收起限额、显示顺序、绕槽条目收养。
- rc.2 的格子问题一并解决：收起保留 N 行时，网格里不留空格子。
- 认错对象的风险被结构特征挡住；认不出仍然是安全失效。

### Negative Consequences / Accepted Tradeoffs

- 判定依赖「面板行有 `aria-label`」这一结构推断。DSH 若改掉它，插件退回「什么都不做」。
- `findPanelNav` / `findSidebarRoot` 每次渲染都走几层祖先、各查一次子树——
  侧栏很小，代价可忽略，但没有缓存。

### Risks

- DSH 下一版若把面板行挪进 `<nav>` 之外的容器（例如渲染成 `<ul>`），发现逻辑会再次
  失效——表现为网格 / 折叠静默失灵，不会弄坏界面。

---

## Implementation Notes

- `isPanelNav` 用 `button[aria-label],[role=button][aria-label]` 判定；设置页那个
  `<nav>` 的按钮没有 `aria-label`，因此不会被认成面板列表。
- 发现顺序很重要：**先直接子、后子树**。rc.1 里 `<nav>` 是根节点的直接子元素，
  直接命中；rc.2 里根节点的直接子元素没有 `<nav>`，才落到子树查找。
- 收起限额的计数单位从「行按钮」改成「`<nav>` 的直接子元素」：rc.1 两者同一个，
  rc.2 是 DSH 的格子——按格子隐藏，网格里才不会留下空格子。
- 放回绕槽条目时，参考元素必须是根节点的子元素：rc.2 里 `<nav>` 在滚动视口内，
  不是根节点的子元素，`insertBefore(entry, nav)` 会抛异常，故按「记录的相邻元素 →
  `<nav>`（若它是根的子元素）→ 追加」三级回退。
- 相关代码：`src/client.js` 的 `isPanelNav` / `panelNavIn` / `findPanelNav` /
  `findSidebarRoot` / `rowOf` / `orderOf` / `applyNav` / `applyGrid` / `releaseEntry`。
- 测试见 `test/smoke.js`：假 DOM 同时建模两种形状（`makeSidebar(labels, shape)`），
  同一组断言跑两遍。

## Review Date

触发条件：DSH 给面板入口提供官方身份（data 属性或槽位强制），或侧栏结构再次变化
（面板列表既不是某个祖先的直接子、也不是它的子树里的 `<nav>`）——任一发生即复审本
ADR。
