# 设计说明 / Design notes

这个文档记录 `toomuch-plugins` 做什么、怎么做、依赖哪些约定。改代码前先看这里。

## 1. 目标

DSH Web 左侧栏从上到下是：品牌行 → 新会话 → **全局面板入口** → 工作区 → 设置。

「全局面板入口」这一列会随着装的插件越来越多：插件、插件市场、定时任务、MCP Studio、
上下文、技能管理器、系统监控……每多一个插件，这一列就多一行，大约每行 40px。

本插件有两个目标：

1. **在需要时把这列收起来，把空间还给工作区**（0.1 起）。
2. **给这列一个可配置的显示方式**（0.2 起）：网格模式 —— 只显示图标、文字放进悬停提示；
   每行图标数量 2–4 可调；收起时可保留前 N 个入口（列表模式按个数，网格模式按行数）；
   图标尺寸三档（小 / 中 / 大，中为默认）。
   配置页在设置的左侧菜单里（「侧栏面板显示」一项）。

## 2. 范围

做：

- 折叠侧栏根节点下的**全局面板入口列表**（一个 `<nav>`）。
- 在侧栏底部放一个开关，随时展开 / 收起。
- 记住选择，刷新后保持。
- **网格显示模式**：宽栏下把入口列表排成图标网格，隐藏文字、以原生 `title` 显示
  悬停提示；每行图标数 2–4 可设。
- **收起时保留部分入口**：列表模式保留前 0–5 个，网格模式保留前 0–3 行
  （行数 × 列数即图标数）；0 = 全部收起，即 0.1 的原始行为。
- **配置页**：通过 `settings.section` 槽注册到设置的左侧菜单（真实先例：`dsh-prompt`
  的「提示工具箱」、`dsh-cost-meter` 的用量页）。
- **插件显示顺序**：配置页里逐个从下拉框挑选面板，列表顺序即显示顺序；上限 20 项，
  重复项保存时自动去掉。用 CSS `order` 重排（不动 React DOM 调和）。下拉框除槽位面板
  外也列出绕槽插入的 `data-dsh-*-entry` 条目（今日值得读 / 全局搜索 / 容器…，按属性名
  通用发现）；被列出的条目会被收养进 `<nav>`（CSS `order` 才够得着），清空顺序后放回。
  设置页随 `sidebar.panellist` 槽位变化重渲染，后注册的面板（如上下文洞察，挂在设置
  开关后）也会出现。
- **图标尺寸**：小（12px）/ 中（默认 = 侧栏原生 16px）/ 大（24px）三档。给 `<nav>`
  打标记类、CSS 覆盖行内 svg 的 `width`/`height`（sprite symbol 带 viewBox，
  随视口缩放；`!important` 是因为第三方入口可能用行内样式定尺寸）。
- **点击计数**：面板入口被点击时，客户端把 id 报给自己的 Host 半边
  （手写 Typert 远程调用 `spcClicks.recordClick`），落盘到
  `~/.dsh/plugins/dsh-toomuch-plugins/click-counts.json`。
- **工作区收藏与项目筛选**（0.4.0）：项目右键菜单第一行「我的最爱」（开关，已收藏的
  项目名后面有黄星）；「视图选项 → 筛选会话」里三个开关 —— 仅显示我的最爱、仅显示最近
  n 天、仅显示最新 m 个项目，按「与」组合；n（1–99，默认 7）与 m（1–9，默认 3）在配置页。
  见第 8 节。
- **使用率分析**（**0.3.3 不提供入口**）：页面本身不在这个包里——它在
  `packages/dsh-plugin-insight` 的 client 半边（整页，不是弹窗），后台继续采集
  使用率数据。**但这一版不提供入口**：页面上任何地方都不显示它（底部没有那个柱状
  图标，页面也没有任何可达的入口），下个版本再开放。

不做（有意为之）：

- **不碰品牌行、新会话、设置**。在 Linux / Windows 上，品牌行里的「收起侧栏」按钮是
  唯一的收起入口，把它一起藏掉等于少一个功能。
- **不隐藏任何面板本身**，只是不显示入口；面板内容从别处照常能打开。
- **不改宿主的视图状态**。三个筛选开关只隐藏 DOM 行，不写宿主的 viewing store、
  不改归档筛选、不动用户的排序与分组选择 —— 关掉开关一切照旧。
- **不注入任何 DSH 内部模块、不读写 DSH 配置**（不用 `ctx.configForms` 那套 Host 设置
  传输），不改动别的插件 / 宿主的行为。自己的偏好仍只写 localStorage；唯一的落盘
  是自己 Host 半边的私有计数文件（`click-counts.json`），不碰其他任何文件。

## 3. 依赖的 DOM 约定

插件不 import DSH 的内部包，纯粹靠下面几条约定工作（都来自
`@deepseek-ai/dsh-client-ui-sidebar`）：

| 约定 | 用途 |
| --- | --- |
| 侧栏根节点的子树里有一个**装面板行的 `<nav>`**：≤ v0.2.2-rc.1 它是根节点的**直接子元素**，v0.2.2-rc.2 起挪进了滚动视口（`root > scrollRegion > scrollArea > nav`），与工作区一起滚动 | 全局面板入口列表，本插件要折叠的就是它 |
| `<nav>` 的**直接子元素**是一行入口：≤ v0.2.2-rc.1 直接就是按钮，v0.2.2-rc.2 起 DSH 把按钮包进了自己的格子里 | 网格的排版单元、收起限额的计数单位 |
| 面板行是**带 `aria-label` 的按钮**（DSH 的 `PanelRow` 恒有） | 判定「这个 `<nav>` 是不是面板列表」；网格模式把 `aria-label` 镜像成原生 `title` |
| 插槽 `sidebar.footer.action` | 侧栏底部那一行（「设置」旁边） |
| 插槽项的 `wide` 属性 | 窄栏（rail）模式下按钮收成圆形图标 |
| CSS 变量 `--dsw-alias-*` | 主题色 / 圆角 / 间距，跟随 DSH 明暗主题 |
| `<nav>` 下的标准入口是 `button`，图标 `span` 是第一个子元素，**文字 `span` 只在宽栏渲染**；注入式入口可能是 `div`（如全局搜索是 `div role=search`，文字是 `input`） | 网格模式把匹配口径写成 `button` / `role=button` / `[data-spc-adopted]` 三者并集，文字隐藏用 `>*:not(:first-child)` 盖住 `span` 与 `input`；rail 本来就是纯图标列 |
| 宽栏下 DSH 自己的 Tooltip 被禁用（`disabled: wide`），且文字根本没渲染 | 网格模式把 `aria-label` 镜像成原生 `title` 当悬停提示 |
| 插槽 `settings.section` | 设置的左侧菜单里注册一页（真实先例：`dsh-prompt` 的「提示工具箱」） |

**为什么向上回溯而不是直接 `document.querySelector('nav.panelList')`：**
class 名可能被构建工具 hash 或改名，而「装面板行的 `<nav>`」是结构关系，更稳定。
实现里从开关自己的根节点开始逐级向上，每一层先看有没有**直接子** `<nav>`（≤ v0.2.2-rc.1
的形状），再看这一层的子树里有没有装面板行的 `<nav>`（v0.2.2-rc.2 起的形状：面板列表
挪进了滚动视口，滚动视口不是开关的祖先，只认「直接子」会够不着，于是整个网格与
折叠静默失效）。

**侧栏根节点另找一次**：它是第一个「子树里装着面板列表」的祖先。旧版它就是 `<nav>`
的父节点；v0.2.2-rc.2 起 `<nav>` 进了滚动视口，根节点不再是它的父节点，但绕槽插入
的 `data-dsh-*-entry` 条目仍挂在根节点上，收养 / 放回都要找它。详见
[ADR-0004](adr/0004-面板列表发现.md)。

## 4. 状态与持久化

两份状态，都用 `localStorage`，都是「读不出来就用安全默认值」：

| key | 内容 | 默认 / 读取规则 |
| --- | --- | --- |
| `dsh.sidebar-panel-collapse` | 折叠状态 | 只有明确存了 `'expanded'` 才算展开，其余按收起 |
| `dsh.sidebar-panel-collapse.display` | 显示与筛选偏好 `{grid, columns, collapsedCount, collapsedRows, order, iconSize, favoritesOnly, recentOnly, latestOnly, recentDays, latestCount}` | JSON 对象；`grid` 必须是 `true` 才开；`columns` 取整且必须在 2–4，否则回 3；`collapsedCount` 取整且必须在 0–5，否则回 0；`collapsedRows` 取整且必须在 0–3，否则回 0；`order` 必须是数组，元素只保留非空字符串、去重、最多 20 个，否则回 `[]`；`iconSize` 只认 `'sm'`/`'lg'`，其余（含缺省）回 `'md'`；三个筛选开关必须是严格 `true` 才算开；`recentDays` 取整且在 1–99，否则回 7；`latestCount` 取整且在 1–9，否则回 3；整条读取 / 解析失败回默认对象 |

- 折叠默认 **收起**（首次安装即刻生效，这是这个插件存在的意义）。
- 显示偏好默认**关闭网格、每行 3 个、收起时保留 0 个（全部收起）**，即不改变原生外观与 0.1 行为。
- 写入失败（隐私模式等）不报错，只是这次选择不持久。

## 5. 数据流

折叠：

```
用户点开关
   └─> setCollapsed(next)
          ├─> React 重新渲染（按钮文案 / 图标变化）
          └─> useEffect 重新执行 applyNav(wide, collapsed, prefs)
                 ├─> 限额 = 收起时 ?（网格 ? collapsedRows×columns : collapsedCount）: ∞
                 ├─> nav.style.display = 限额为 0 ? 'none' : ''
                 └─> 逐个入口：前「限额」个去掉 data-spc-hidden，其余打上（CSS 隐藏）
          └─> writeStored(collapsed)  // localStorage
```

显示偏好：

```
设置页勾选 / 选列数
   └─> writePrefs()  // localStorage + 通知 prefsListeners
          ├─> 设置页自己 setState 重渲染
          └─> 底部开关组件 setState 重渲染
                 └─> useEffect 重新执行 applyGrid()
                        ├─> nav 加/去 class dsh-spc-grid，
                        │   style 设 --dsh-spc-grid-cols（2–4）
                        └─> 每个入口（button 或收养的 div）：把 aria-label 镜像成 title
                            （关网格时再移除）
```

`useEffect` 在每次渲染后都重新套用 `display` / 网格样式，因为 DSH 侧栏重渲染时可能
重建这个 `<nav>`，只设一次会被覆盖。网格 CSS 全部用**结构关系选择器**
（`:is(button,[role=button],[data-spc-adopted])` 这类），不依赖侧栏的 hash class 名；形状变了选择器自然
失配，列表退回普通样式 —— 与折叠同样的安全失效。
隐藏计数（`applyNav`）、网格单元样式、title 镜像三处用**同一口径**：按钮、
`role=button`、带 `[data-spc-adopted]` 收养标记的入口。漏掉任何一类都会出现
「多出来的入口永远不被隐藏」的错位（全局搜索这种 `div role=search` 就靠收养标记入列）。

### 收养注入式入口

一部分插件（今日值得读、全局搜索、容器等）不走标准的 `sidebar.panellist` 槽，而是
自建元素直接插到侧栏根节点（logoRow 之后、`<nav>` 之前），并用 `data-dsh-*-entry`
属性做族内排序。网格开启时 `adoptEntries()` 把这些入口挪进 `<nav>` 参与网格，关闭时
`releaseEntries()` 按收养前记下的相邻元素还原位置。它们自己的重放置观察器只在入口
**脱离侧栏根节点**时才重新插入 —— `<nav>` 仍在根节点内，所以收养不会触发回弹。
属性名不再写死清单：`domEntryId()` 遍历元素属性，凡 `data-dsh-*` 前缀 + `-entry`
后缀的名字都算（CSS 没有属性名通配符，只能 JS 遍历），新插件沿用同一约定即自动纳入。
网格开启时全量收养；列表模式设了显示顺序时只收养被列出的条目（未列出的留在原位——
它们在 `<nav>` 外的另一个盒子里，CSS `order` 碰不到），清空顺序全量放回。
点击计数同样按属性名向上找条目（点图标、点搜索框也计数），且只认当前侧栏作用域内的。
决策背景与被否掉的备选见 [ADR-0001](adr/0001-sidebar-entry-discovery.md)。

## 7. 插件操作记录（0.4.0）

### 数据来源

**不比听事件，比状态。** 早先的实现监听 DSH 插件管理器的 `plugin-manager/operation`
事件，实测漏记录：这个事件只在应用内那条路径（设置里的插件页）发出来，而装/删插件
还可以发生在插件市场、`dsh` 命令行，那些路径根本不会往运行中的应用发事件 —— 市场是
shell 出去调 CLI 的。既然只有部分路径会广播，就不能靠广播。

所有路径唯一都改的东西是 **profile 清单**（`<profile>/package.json`）：

- `dependencies`：装了什么、版本是多少 —— 安装 = 键出现，删除 = 键消失；
- `dsh.profile.bundles`：哪些插件包是启用的 —— 键在这个数组里 = 启用。

所以记录器每隔 `SYNC_INTERVAL_MS`（5 秒）以及窗口打开时，把清单和日志里上次记下的
快照（`known`）比一次，把差异写成记录。

代价与边界：

- 时间戳是**发现时间**，不是精确的操作时间，误差在一个轮询周期内。
- 两次比对之间发生的「删了又装回同一版本」会互相抵消、不留记录。（升级本来也不该留。）
- 单个 loader entry 的开关（`reason: 'plugin'`，不经 manifest）不在覆盖范围内 —— 它只
  出现在插件的内部启用状态里，没有可比的持久化清单项。**这是有意为之的取舍**，见下方
  「后续扩展」。

### 名称怎么来

比对的是 manifest 的依赖键，本身就是包名，不需要再从 loader entry id 反查模块名。

### 升级怎么排除

DSH 的升级 = 先删包再装同一个包，两步都跑 npm，间隔是秒到分钟级。所以：

- 比对发现删除，**立刻写盘**——删除之后往往紧跟着重启，只留在内存里的记录会丢；
- 同时把它记成「可回撤」的，窗口 10 分钟；
- 窗口内紧接着的重装如果版本**不同** → 判定为升级，把刚写的那条删除记录**回撤**掉，
  重装本身也不写；
- 版本**相同** → 是真的「删了又装回去」，两条都保留；
- 窗口内等不到重装 → 这条删除就留在日志里。

> 取舍：升级如果比 10 分钟还慢，日志里会留下一条多余的「删除」。
> 反过来（先扣着不写）会让真实删除在重启后彻底消失，代价更大。

早期版本是「先扣在内存、等打开窗口才写盘」，实测会漏记录：删除后立刻打开窗口，
3 秒的判定期还没过，什么都不会写；关掉窗口后再没打开过，这条记录就永远不落盘。

### 启停怎么判定

只看包在不在 `dsh.profile.bundles` 里，和上次记下的对比：新进入数组 = 启用，离开 =
禁用。因为比的是**最终状态**而不是某个事件的措辞，那些只改兼容性、不改开关的操作
（版本豁免）自然就不会留下记录。这也是原来那套「操作前后各读一次」的判定的替代 ——
现在没有事件可读了，状态差本身就是判定。

### 展示窗口

- 「安装/删除」：全量；「启用/禁用」：只显示最近 30 天（滚动窗口，由 Host 半边在
  `list()` 里过滤）。
- 两个标签页都按时间**倒序**返回（`list()` 里 `reverse().sort(newestFirst)`，稳定排序，
  时间相同的时候保留写入顺序的倒序）。
- 每行的操作列是 16px 线条图标（描边 1.8），按状态色着色：**安装 = 绿色**、**启用 = 绿色**
  （电源符号），**删除 = 红色**、**禁用 = 红色**（电源符号加一道斜杠）。同时给图标一个
  `aria-label`（「安装」等），屏幕阅读器能读出来。行高下文字标签看不清，所以不用文字。
- 插件名 14px 半粗，时间 13px，都比正文大一号。
- 首次安装**不罗列任何插件**：profile 里已经装着的插件是这份日志存在之前就装上的，
  不是新闻。当前状态直接成为比对的基线（`known`），只有之后的装/删/启停才是记录。
  旧版本日志里的 `baseline` 行也在读取时丢掉。

### 文件格式

`~/.dsh/plugins/dsh-toomuch-plugins/plugin-history.json`：

```json
{
  "version": 2,
  "known": {
    "packages": { "dsh-docker": "0.16.1" },
    "enabled": ["dsh-docker"]
  },
  "events": [
    { "action": "install", "name": "dsh-docker", "version": "0.16.1", "time": "2026-11-09T02:19:28.000Z" },
    { "action": "disable", "name": "dsh-docker", "version": null, "time": "2026-11-09T02:20:11.000Z" }
  ]
}
```

- `known`：上次比对时的 profile 状态，是下一次比对的对象。
- `events`：展示用的记录，上限 2000 条（超出丢最旧的）—— 这是日志，不是数据库。
- `version: 1` 的老文件没有 `known`：读到就**静默收养**当前状态当基线，不补记任何记录，
  同时升到 2。所以升级本插件本身不会在记录里凭空多出一堆安装。

## 8. 工作区收藏与项目筛选（0.4.0）

### 要解决什么

工作区一多，侧栏就成了长列表。「我的最爱」给常看的项目一个标记，三个筛选开关把
其余项目临时藏起来 —— 平时只看关注的那几个，要找别的再关掉开关。

### 收藏

- **存在哪**：`~/.dsh/plugins/dsh-toomuch-plugins/favorites.json`，一个路径数组。
  放在插件自己的目录，不碰 DSH 配置与会话，插件重装也不丢。
- **用什么当键**：项目的**绝对路径**，不是 `workspaceId`。工作区删掉再加回同一个
  目录时宿主会发一个新的 UUID，但目录还是那个目录 —— 对用户来说是同一个项目，
  星不该丢。
- **怎么改**：客户端只发一个 `spcFavorites.toggle(path)`，Host 半边读写文件并返回
  完整列表；客户端用返回值覆盖本地镜像。收藏的权威永远在 Host 那一半。
- **写盘**：原子写（临时文件 + `rename`），写一半崩溃只会留下上一份完整清单。
  上限 500 条，单条路径 1024 字符。

### 右键菜单

`ctx.contextMenus.register({ target: 'workspace', order: 50 })`。宿主自己的
「重命名」是 order 100、「删除」是 300，所以 50 就是菜单的第一行。图标按 key 从
`contextMenu.icon` 这个 keyed 槽里取，因此先注册 `workspace.favoriteOn`（实心星）与
`workspace.favoriteOff`（空心星）两枚。`observe` 挂上收藏来源：菜单开着的时候星标改了，
菜单会自己重解析。

### 三个筛选开关

宿主「视图选项 → 筛选会话」是它自己写死的 `items` 数组，**没有插件槽位**，所以只能
在菜单弹出后往 DOM 里插三行：

- **认哪个菜单**：宿主给 `type: 'label'` 的分组标题渲染成 `role="presentation"` 的行。
  视图选项菜单有三个这样的标题（分组 / 排序 / 筛选），会话右键菜单一个都没有 ——
  这就是判据。菜单面板本身用 `data-menu-material` 定位（primitives 的 Menu 恒带）。
- **行从哪来**：**克隆宿主的最后一项**（「仅显示已归档」），再把文案换掉、勾装上。
  行高、内边距、悬停态、主题色都跟着宿主走，不用自己复刻一套。克隆来的**图标要去掉**
  ——那是它那一项的图标（归档的箱子），与开关无关。
- **勾自己画**：宿主只给「已选中」的项画勾（在按钮末尾），我们的三项是独立开关，
  勾由自己造一个（12px 勾线），未勾上时用 `[data-off]` 隐藏。
- **勾的状态每次都要同步**：宿主每次打开菜单都重建这一片 DOM，克隆出来的行是
  **全新节点** —— 属性、状态都是初始值。所以「已经注入过」时也要再跑一遍
  `syncFilterRows()`，按当前偏好重写勾的显隐与 `aria-pressed`。
- **CSS 的祖先类必须真的存在**：第一版写的是 `.dsh-spc-menuItem .dsh-spc-menuCheck`，
  而 `dsh-spc-menuItem` 从未被添加到任何元素上 —— 规则永不生效，勾于是常显，
  看起来就是「点了没反应」。
- **点它不关菜单**：用户常常要连着勾两个，所以 `preventDefault` + `stopPropagation`，
  只翻自己的开关。勾选状态由 `.dsh-spc-menuCheck[data-off]` 控制。

### 筛选怎么算

纯计算在客户端，不碰 DOM（`visibleWorkspaceIds`）：

1. **最后活跃时间** = 该项目名下所有会话里最大的 `updatedAt`；一个会话都没有记 0。
   不用工作区注册时间 —— 注册时间跟用户还在不在用这个项目没关系。
2. **仅显示最近 n 天**：最后活跃时间在 n 天内；从未有会话的项目算最旧，不出现。
3. **仅显示最新 m 个项目**：按最后活跃时间排序取前 m 个，并列时按路径稳定排序。
4. **仅显示我的最爱**：路径在收藏列表里。
5. 三个条件按**「与」**组合。
6. **合格的项目的父节点要留着**。工作区树里若子项目合格，它的父目录那一行也要
   显示 —— 否则子项目就成了没有父行的孤儿行。父节点只是**容器**：它自己不符合
   条件，所以它的会话仍然不显示。判定用目录边界（父路径后面必须跟分隔符），
   `/repo` 不是 `/repository` 的父。

   于是有两个集合：`qualifying`（自己符合条件，会话照常显示）与 `visible`
   （行要显示的 = qualifying ∪ 它们的祖先）。

### 宿主真实的项目行（2026-11-17 实测）

**别信源码，信跑着的宿主。** 本机同时装了两套 DSH，源码里项目行是
`data-row-key="workspace:<id>"` + `.projectText > .title`，但**跑着的那个版本**
（v0.2.2-rc.3 的新版工作区浏览器）实际是：

```html
<div class="bw-row bw-container-row" data-row-key="ws-<id>" role="treeitem"
     style="--bw-indent: 0px;">
  <span class="bw-chevron">…</span>              <!-- 展开箭头 -->
  <span class="bw-row-icon bw-folder-cell">…</span>  <!-- 文件夹图标 -->
  <span class="bw-row-label" title="名字">名字</span> <!-- 标签 -->
  <span class="bw-row-count">3</span>            <!-- 会话数徽标（异步出现） -->
  <span class="bw-row-actions">…</span>          <!-- 悬停才出现的动作区 -->
</div>
```

会话行是 `data-row-key="session:<sessionId>"`，行与行是**兄弟**（不在项目行里）。

两处差异让第一版整体失效：key 前缀从 `workspace:` 变成了 `ws-`，标签从
`.projectText > .title` 变成了 `.bw-row-label`。于是项目行**一个都没匹配上** ——
星号插不进去、项目行也藏不住（会话行匹配上了，所以表现为「别的项目会话打不开、
项目行还在」）。

### 怎么认行：不靠前缀，靠 id

宿主改过 key 前缀，所以**不能**按前缀找行。改成按 id 尾部匹配：工作区的 id 是
知道的（工作区快照里有），行 key 的尾部就是它：

| key | id 部分（最后一个冒号之后） |
| --- | --- |
| `ws-<uuid>` | `ws-<uuid>`（没有冒号，整串就是） |
| `session:<uuid>` | `<uuid>` |
| `session:session-<uuid>` | `session-<uuid>` |

`keyIsId(key, id)` = 尾部以 id 结尾 **且** id 前一个字符不是 id 字符（避免一个 id
是另一个 id 的后缀时误判）。宿主再换前缀也不影响。

### 标签怎么认：文字非空、且自己不含子元素

不能用「文字等于整行文字」—— 宿主会**异步**补一个会话数徽标，整行文字随之改变，
判定就失配，新渲染的行会找不到标签。改成：行里**文字非空、且自己不含子元素**的
元素，取 DOM 顺序第一个。

- 新版：`.bw-row-label`（纯文字、无子元素）✓；会话数徽标在它后面，靠顺序排后面。
- 旧版：`.projectText` 含子元素不算，内层的 `.title` 才是 ✓。

### 星号插在哪（踩过的坑）

| 插在哪 | 结果 |
| --- | --- |
| 标签**里面** | 名字长了星号一起被裁掉（标签带 `overflow:hidden + ellipsis`） |
| 行尾（动作区之前） | 被标签的 `flex:1` 挤到整行最右，看着像没画出来 |
| **标签之后、作为兄弟节点** | 对：标签改成 `flex:0 1 auto`（只占内容宽度、可以被压缩出省略号），星号紧跟其后 |

**React 会把星号删掉**：项目行是 React 渲染的，宿主重建这行的 children 时不认我们
插进去的节点，会连它一起删。所以 MutationObserver 同时看 `removedNodes`：看到星号
消失就重画一次补回来。

### 怎么落到界面上

宿主没给项目行留装饰位，所以星号与显隐同样是对 DOM 的增量：

- 项目行 `[data-row-key^="workspace:"]`，会话行 `[data-row-key^="session:"]`；
  `data-row-key="workspace:"`（空后缀）是「未分组」桶，不是项目，不参与。
- 星号插在**项目名后面**（紧挨名字），常显，不靠悬停。位置踩过坑，见下。
- 被筛掉的行打 `data-spc-fhide`，样式表给 `display:none !important`；关掉开关时
  整批摘掉，不改宿主的任何状态。
- 被筛掉的项目底下的会话也打标记（平铺视图、搜索结果同一口径）；不属于任何项目的
  会话不受影响。
- 重算的触发：偏好变化、收藏变化、工作区 / 会话快照变化，以及 `MutationObserver`
  发现新的相关节点（宿主重渲染、菜单弹出）。多次触发合并成一个 80ms 的时间窗。

## 9. 兼容性风险

- 本插件依赖 DSH 内部 DOM 结构。DSH 改版后如果侧栏结构变了，最坏情况是**找不到目标
  `<nav>`，什么都不做** —— 不会报错、不会弄坏界面，属于安全失效。
- DSH v0.2.2-rc.2 把面板列表挪进了滚动视口（与工作区一起滚动），本插件已同时认新旧
  两种形状，见 [ADR-0004](adr/0004-面板列表发现.md)。
- 不 import DSH 内部包，因此 DSH 升级不会让插件直接加载失败。
- 样式全部走 `--dsw-alias-*` 变量，不写死颜色；主题改动时不会失配。

49a. 父目录不合格、子项目也不合格时，父子两行都隐藏。
