# 设计说明 / Design notes

这个文档记录 `toomuch-plugins` 做什么、怎么做、依赖哪些约定。改代码前先看这里。

## 1. 目标

DSH Web 左侧栏从上到下是：品牌行 → 新会话 → **全局面板入口** → 工作区 → 设置。

「全局面板入口」这一列会随着装的插件越来越多：插件、插件市场、定时任务、MCP Studio、
上下文、技能管理器、系统监控……每多一个插件，这一列就多一行，大约每行 40px。

本插件有两个目标：

1. **在需要时把这列收起来，把空间还给工作区**（0.1 起）。
2. **给这列一个可配置的显示方式**（0.2 起）：网格模式 —— 只显示图标、文字放进悬停提示；
   每行图标数量 2–4 可调；收起时可保留前 N 个入口（列表模式按个数，网格模式按行数）；
   图标尺寸三档（小 / 中 / 大，中为默认）。
   配置页在 设置 → 内置插件 里。

## 2. 范围

做：

- 折叠侧栏根节点下的**全局面板入口列表**（一个 `<nav>`）。
- 在侧栏底部放一个开关，随时展开 / 收起。
- 记住选择，刷新后保持。
- **网格显示模式**：宽栏下把入口列表排成图标网格，隐藏文字、以原生 `title` 显示
  悬停提示；每行图标数 2–4 可设。
- **收起时保留部分入口**：列表模式保留前 0–5 个，网格模式保留前 0–3 行
  （行数 × 列数即图标数）；0 = 全部收起，即 0.1 的原始行为。
- **配置页**：通过 `settings.plugins.tab` 槽注册到 设置 → 内置插件。
- **插件显示顺序**：配置页里逐个从下拉框挑选面板，列表顺序即显示顺序；上限 20 项，
  重复项保存时自动去掉。用 CSS `order` 重排（不动 React DOM 调和）。下拉框除槽位面板
  外也列出绕槽插入的 `data-dsh-*-entry` 条目（今日值得读 / 全局搜索 / 容器…，按属性名
  通用发现）；被列出的条目会被收养进 `<nav>`（CSS `order` 才够得着），清空顺序后放回。
  设置页随 `sidebar.panellist` 槽位变化重渲染，后注册的面板（如上下文洞察，挂在设置
  开关后）也会出现。
- **图标尺寸**：小（12px）/ 中（默认 = 侧栏原生 16px）/ 大（24px）三档。给 `<nav>`
  打标记类、CSS 覆盖行内 svg 的 `width`/`height`（sprite symbol 带 viewBox，
  随视口缩放；`!important` 是因为第三方入口可能用行内样式定尺寸）。
- **点击计数**：面板入口被点击时，客户端把 id 报给自己的 Host 半边
  （手写 Typert 远程调用 `spcClicks.recordClick`），落盘到
  `~/.dsh/plugins/dsh-toomuch-plugins/click-counts.json`。

不做（有意为之）：

- **不碰品牌行、新会话、设置**。在 Linux / Windows 上，品牌行里的「收起侧栏」按钮是
  唯一的收起入口，把它一起藏掉等于少一个功能。
- **不隐藏任何面板本身**，只是不显示入口；面板内容从别处照常能打开。
- **不注入任何 DSH 内部模块、不读写 DSH 配置**（不用 `ctx.configForms` 那套 Host 设置
  传输），不改动别的插件 / 宿主的行为。自己的偏好仍只写 localStorage；唯一的落盘
  是自己 Host 半边的私有计数文件（`click-counts.json`），不碰其他任何文件。

## 3. 依赖的 DOM 约定

插件不 import DSH 的内部包，纯粹靠下面几条约定工作（都来自
`@deepseek-ai/dsh-client-ui-sidebar`）：

| 约定 | 用途 |
| --- | --- |
| 侧栏根节点下有一个**直接子元素** `<nav>`，class 为 `panelList` | 全局面板入口列表，本插件要折叠的就是它 |
| 插槽 `sidebar.footer.action` | 侧栏底部那一行（「设置」旁边） |
| 插槽项的 `wide` 属性 | 窄栏（rail）模式下按钮收成圆形图标 |
| CSS 变量 `--dsw-alias-*` | 主题色 / 圆角 / 间距，跟随 DSH 明暗主题 |
| `<nav>` 下的标准入口是 `button`，图标 `span` 是第一个子元素，**文字 `span` 只在宽栏渲染**；注入式入口可能是 `div`（如全局搜索是 `div role=search`，文字是 `input`） | 网格模式把匹配口径写成 `button` / `role=button` / `[data-spc-adopted]` 三者并集，文字隐藏用 `>*:not(:first-child)` 盖住 `span` 与 `input`；rail 本来就是纯图标列 |
| 宽栏下 DSH 自己的 Tooltip 被禁用（`disabled: wide`），且文字根本没渲染 | 网格模式把 `aria-label` 镜像成原生 `title` 当悬停提示 |
| 插槽 `settings.plugins.tab` | 设置 → 内置插件 区里注册一页（真实先例：`settings-plugin-inventory` 的「插件列表」） |

**为什么向上回溯而不是直接 `document.querySelector('nav.panelList')`：**
class 名可能被构建工具 hash 或改名，而「直接子元素 `<nav>`」是结构关系，更稳定。
实现里从开关自己的根节点开始，逐级向上找「第一个含直接子 `<nav>` 的祖先」，直到
`document.body` 为止 —— 侧栏根节点一定是其中之一。

## 4. 状态与持久化

两份状态，都用 `localStorage`，都是「读不出来就用安全默认值」：

| key | 内容 | 默认 / 读取规则 |
| --- | --- | --- |
| `dsh.sidebar-panel-collapse` | 折叠状态 | 只有明确存了 `'expanded'` 才算展开，其余按收起 |
| `dsh.sidebar-panel-collapse.display` | 显示偏好 `{grid, columns, collapsedCount, collapsedRows, order, iconSize}` | JSON 对象；`grid` 必须是 `true` 才开；`columns` 取整且必须在 2–4，否则回 3；`collapsedCount` 取整且必须在 0–5，否则回 0；`collapsedRows` 取整且必须在 0–3，否则回 0；`order` 必须是数组，元素只保留非空字符串、去重、最多 20 个，否则回 `[]`；`iconSize` 只认 `'sm'`/`'lg'`，其余（含缺省）回 `'md'`；整条读取 / 解析失败回默认对象 |

- 折叠默认 **收起**（首次安装即刻生效，这是这个插件存在的意义）。
- 显示偏好默认**关闭网格、每行 3 个、收起时保留 0 个（全部收起）**，即不改变原生外观与 0.1 行为。
- 写入失败（隐私模式等）不报错，只是这次选择不持久。

## 5. 数据流

折叠：

```
用户点开关
   └─> setCollapsed(next)
          ├─> React 重新渲染（按钮文案 / 图标变化）
          └─> useEffect 重新执行 applyNav(wide, collapsed, prefs)
                 ├─> 限额 = 收起时 ?（网格 ? collapsedRows×columns : collapsedCount）: ∞
                 ├─> nav.style.display = 限额为 0 ? 'none' : ''
                 └─> 逐个入口：前「限额」个去掉 data-spc-hidden，其余打上（CSS 隐藏）
          └─> writeStored(collapsed)  // localStorage
```

显示偏好：

```
设置页勾选 / 选列数
   └─> writePrefs()  // localStorage + 通知 prefsListeners
          ├─> 设置页自己 setState 重渲染
          └─> 底部开关组件 setState 重渲染
                 └─> useEffect 重新执行 applyGrid()
                        ├─> nav 加/去 class dsh-spc-grid，
                        │   style 设 --dsh-spc-grid-cols（2–4）
                        └─> 每个入口（button 或收养的 div）：把 aria-label 镜像成 title
                            （关网格时再移除）
```

`useEffect` 在每次渲染后都重新套用 `display` / 网格样式，因为 DSH 侧栏重渲染时可能
重建这个 `<nav>`，只设一次会被覆盖。网格 CSS 全部用**结构关系选择器**
（`:is(button,[role=button],[data-spc-adopted])` 这类），不依赖侧栏的 hash class 名；形状变了选择器自然
失配，列表退回普通样式 —— 与折叠同样的安全失效。
隐藏计数（`applyNav`）、网格单元样式、title 镜像三处用**同一口径**：按钮、
`role=button`、带 `[data-spc-adopted]` 收养标记的入口。漏掉任何一类都会出现
「多出来的入口永远不被隐藏」的错位（全局搜索这种 `div role=search` 就靠收养标记入列）。

### 收养注入式入口

一部分插件（今日值得读、全局搜索、容器等）不走标准的 `sidebar.panellist` 槽，而是
自建元素直接插到侧栏根节点（logoRow 之后、`<nav>` 之前），并用 `data-dsh-*-entry`
属性做族内排序。网格开启时 `adoptEntries()` 把这些入口挪进 `<nav>` 参与网格，关闭时
`releaseEntries()` 按收养前记下的相邻元素还原位置。它们自己的重放置观察器只在入口
**脱离侧栏根节点**时才重新插入 —— `<nav>` 仍在根节点内，所以收养不会触发回弹。
属性名不再写死清单：`domEntryId()` 遍历元素属性，凡 `data-dsh-*` 前缀 + `-entry`
后缀的名字都算（CSS 没有属性名通配符，只能 JS 遍历），新插件沿用同一约定即自动纳入。
网格开启时全量收养；列表模式设了显示顺序时只收养被列出的条目（未列出的留在原位——
它们在 `<nav>` 外的另一个盒子里，CSS `order` 碰不到），清空顺序全量放回。
点击计数同样按属性名向上找条目（点图标、点搜索框也计数），且只认当前侧栏作用域内的。
决策背景与被否掉的备选见 [ADR-0001](adr/0001-sidebar-entry-discovery.md)。

## 6. 代码结构

| 文件 | 角色 |
| --- | --- |
| `src/index.js` | Host 半边。提供 `spcClicks` / `spcHistory` 两个 Typert 远程服务（手写 `typertRemote` 绑定 + 原型方法标记，走 gateway 的 src 描述符兜底），并把客户端报来的面板点击累加进 `click-counts.json` |
| `src/history.js` | Host 半边。插件操作记录器：监听 `plugin-manager/operation`，写出 `plugin-history.json`，负责升级识别、启停状态比对与首次扫描 |
| `src/client.js` | Client 半边。全部逻辑在这里：`FooterToggle`（折叠 + 网格 + 顺序套用 + 操作记录图标）、`ActivityWindow`（操作记录窗口，注册在 `shell.overlay`）、`DisplaySettingsTab`（设置页）、localStorage 读写与偏好广播、点击采集与 `$mount` 远程贡献 |
| `test/smoke.js` | 零依赖冒烟检查：`node test/smoke.js`。桩掉 `window.__ModuleLoader__` / react，断言两个槽注册的元数据 + 设置页读写偏好的默认值规则。不进 npm 包 |
| `cordis.patch.yml` | 往 profile 里插入一行插件加载记录（包名 `dsh-toomuch-plugins`，即仓库根） |
| `locale/{en,zh}.json` | 插件列表里显示的标题和描述 |

`package.json` 的 `exports` 把 Host 半边指向 `.`（`src/index.js`），Client 半边指向
`./client`（`src/client.js`）；DSH 通过这两个入口分别加载。

## 7. 插件操作记录（0.4.0）

### 数据来源

DSH 的插件管理器（`@deepseek-ai/dsh-plugin-manager`）在每次安装、删除、启用/禁用、
版本豁免时都会 `ownerContext.parallel('plugin-manager/operation', operation)` 发一个事件。
事件形状（取自插件管理器源码）：

| 字段 | 含义 |
| --- | --- |
| `reason` | `install` / `remove` / `plugin`（单个插件开关）/ `bundle`（插件包开关）；版本豁免也走 `bundle` |
| `stage` | `install` / `remove` / `enable` |
| `target` | 包名（安装 / 删除 / 包开关）或 loader entry id（单个插件开关） |
| `enabled` | 开关请求的目标状态 |
| `phase` | `started`（操作前）/ `settled`（操作后） |
| `application` | `applied` / `restart-required` / `overridden` / `failed` / `cancelled` |
| `version` | 操作涉及的版本（删除时是被删包的版本） |
| `time` | ISO 时间戳 |

Host 半边在 `ctx.on('plugin-manager/operation', ...)` 上挂监听 —— cordis 的事件总线是
app 级共享的，别的插件发的事件这里收得到。**只记 `settled` 且 `application` 不是
`failed` / `cancelled` 的操作。**

### 名称怎么来

- 安装 / 删除 / 包开关：`target` 就是包名。
- 单个插件开关：`target` 是 loader entry id，用 `pluginInventory.list()` 换成模块名
  （拿不到就退回 `pluginManager.listPlugins()`）。**必须在 `started` 阶段换**：插件被关掉
  后它的 entry 可能已经不在树里了。

### 升级怎么排除

DSH 的升级 = 先删包再装同一个包，两步都跑 npm，间隔是秒到分钟级。所以：

- 删除一旦确认，**立刻写盘**——删除之后往往紧跟着重启，只留在内存里的记录会丢；
- 同时把它记成「可回撤」的，窗口 10 分钟；
- 窗口内紧接着的重装如果版本**不同** → 判定为升级，把刚写的那条删除记录**回撤**掉，
  重装本身也不写；
- 版本**相同** → 是真的「删了又装回去」，两条都保留；
- 窗口内等不到重装 → 这条删除就留在日志里。

> 取舍：升级如果比 10 分钟还慢，日志里会留下一条多余的「删除」。
> 反过来（先扣着不写）会让真实删除在重启后彻底消失，代价更大。

早期版本是「先扣在内存、等打开窗口才写盘」，实测会漏记录：删除后立刻打开窗口，
3 秒的判定期还没过，什么都不会写；关掉窗口后再没打开过，这条记录就永远不落盘。

### 启停怎么判定

`reason: 'bundle'` 也会被版本豁免复用（豁免只改兼容性文件，不改任何开关状态）。
所以判定不靠事件措辞、而靠**状态比对**：操作前后各读一次「这个包 / 这个 entry 现在
是开是关」（包看 profile manifest 的 `dsh.profile.bundles`，entry 看 loader 的
`disabled`），前后一样就说明这次事件没有真的切换 → 不记。

### 展示窗口

- 「安装/删除」：全量；「启用/禁用」：只显示最近 30 天（滚动窗口，由 Host 半边在
  `list()` 里过滤）。
- 两个标签页都按时间**倒序**返回（`list()` 里 `reverse().sort(newestFirst)`，稳定排序，
  时间相同的时候保留写入顺序的倒序）。
- 每行的操作列是 14px 线条图标，按状态色着色：安装 = 向下箭头、删除 = 向上箭头、
  启用 = 电源开、禁用 = 电源关；同时给图标一个 `aria-label`（「安装」等），屏幕阅读器
  能读出来。行高下文字标签看不清，所以不用文字。
- 首次安装没有历史：扫一遍 profile，把已装的插件（及其开关状态）作为起点记下；这些行
  标记 `baseline`，时间列显示**扫描时间**并追加一个「初始」小标记——既不编造安装时间，
  时间列也不会空着。

### 文件格式

`~/.dsh/plugins/dsh-toomuch-plugins/plugin-history.json`：

```json
{
  "version": 1,
  "events": [
    { "action": "install", "name": "dsh-docker", "version": "0.16.1", "time": "2026-11-09T02:19:28.000Z" },
    { "action": "disable", "name": "dsh-docker", "version": null, "time": "2026-11-09T02:20:11.000Z", "baseline": true }
  ]
}
```

上限 2000 条（超出丢最旧的）—— 这是日志，不是数据库。

## 8. 兼容性风险

- 本插件依赖 DSH 内部 DOM 结构。DSH 改版后如果侧栏结构变了，最坏情况是**找不到目标
  `<nav>`，什么都不做** —— 不会报错、不会弄坏界面，属于安全失效。
- 不 import DSH 内部包，因此 DSH 升级不会让插件直接加载失败。
- 样式全部走 `--dsw-alias-*` 变量，不写死颜色；主题改动时不会失配。

## 9. 验证清单

改完代码后至少过一遍：

1. 装上插件后，侧栏底部「设置」上方出现开关。
2. 默认状态是收起的；点一下展开，再点一下收起。
3. 刷新页面后状态保持。
4. 展开成宽栏（≥ 展开宽度）时开关是一行文字；窄栏（56px rail）时是圆钮。
5. 收起状态下，工作区区域明显变高。
6. 没有全局面板时，开关点了不报错。
7. 浏览器控制台无报错。
8. 设置 → 内置插件 里出现「侧栏面板显示」页。
9. 勾上「网格方式显示」后，宽栏侧栏的入口列表立刻变成图标网格；悬停图标显示该面板名。
10. 选 2 / 4 后每行图标数量立刻变化；刷新页面后网格与列数都保持。
11. 取消勾选后列表恢复原生的文字 + 图标样式，悬停原生 `title` 不残留。
12. rail（窄栏）模式下网格不影响外观（rail 本来就是图标列），开关仍可点。
13. 列表模式选「收起时显示插件数 3」后收起：只剩前 3 个入口可见，其余隐藏；展开恢复全部。
14. 网格模式选「收起时显示行数 1」、每行 3 个后收起：只剩第一行 3 个图标（**不能**多出「单个图标」的一行，全局搜索入口必须参与计数）；改列数后收起限额跟随（行 × 列）。
15. 收起限额设回 0 后收起：整个列表隐藏（与 0.1 行为一致）。
16. 收起限额刷新页面后保持。
17. `node test/smoke.js` 通过。
18. 设置页「插件显示顺序」：下拉框列出全部面板；选中即追加到列表，重复选中保存后
    自动只剩一条；加满 20 项后下拉框禁用；上移 / 下移 / 移除立刻生效并保持。
19. 设置顺序后侧栏入口立刻按该顺序显示（未列出的排在后面）；清空后恢复原生顺序。
20. 收起限额按**视觉顺序**计数（设了顺序后，收起时保留的是顺序里的前 N 个）。
21. 点一个面板入口后，`~/.dsh/plugins/dsh-toomuch-plugins/click-counts.json`
    出现 / 累加该面板的计数；控制台无报错（远程不可用时静默不计数）。
22. 设置页「图标尺寸」：默认「中」按下；选「小」/「大」后侧栏入口图标立刻缩到
    12px / 放大到 24px（列表与网格模式都生效），刷新后保持；选回「中」恢复原生尺寸。
23. 图标尺寸脏值（如 `"xl"`）读回时回「中」。
24. 下拉框里能看到今日值得读 / 全局搜索 / 容器等第三方条目（aria-label 作显示名），
    上下文洞察开启后（设置门控）也会出现（切走再切回设置页触发重渲染）。
25. 把某个第三方条目列进显示顺序：它出现在侧栏列表里并按顺序排；清空顺序后回到
    原来的位置（网格模式开关不受影响）。
26. 点击第三方条目的图标 / 搜索框内部，计数同样累加；页面外区域的点击不计数。
27. 侧栏底部「收起 / 展开全局面板」开关**右侧**出现一个时钟图标；点开是一个带两个标签
    的窗口（「安装/删除」「启用/禁用」），浮在应用之上、不会被侧栏裁掉；Esc 或点遮罩关闭。
28. 首次安装：窗口里已经有一份「初始状态」清单（当前装着的插件 + 它们是开是关），
    `plugin-history.json` 存在且 `baseline` 为 true。
29. 在插件面板里装一个插件 → 「安装/删除」标签出现一条带插件名与时间的记录。
30. 卸载一个插件 → 同标签出现一条「删除」记录。
31. 启用 / 禁用一个插件（或插件包）→ 「启用/禁用」标签出现对应记录，插件名可读。
32. 升级一个插件 → 两个标签都不出现它的记录（升级既不算删除也不算安装）。
33. 把系统时间往前拨一个月以上（或造一条旧记录）→ 旧的启停记录不再显示，安装/删除仍全量在。

- 按 `click-counts.json` 的计数**智能自动排序**（当前只记录，未消费）。
